TabFlick
功能 安装 GitHub

Chrome 也能按使用顺序切标签

Chrome 的 ⌃⇥ 按标签栏顺序走。TabFlick 让它按你实际使用的顺序走，并在按住按键时显示带网页缩略图的切换器 —— 和 ⌘⇥ 切换应用一样。

macOS 13+ Chrome 116+ 开源 · MIT 免费
开始使用 GitHub

按住 ⌃ 连点 ⇥ 浏览候选，松开即切换；也可以直接点卡片。

功能

做的事情不多，但每一件都做到位。

最近使用顺序

⌃⇥ 切到你上一个待过的标签，而不是标签栏里挨着的那个。

来回切换稳定

再点一次就回到出发的标签。按住时只移动游标，松开才提交，中途经过的标签不会被记成用过。

网页缩略图

每张卡片都是网页实时画面，靠样子认标签，不用读被截断的标题。

键盘 · 方向键 · 鼠标

⌃⇥ 与 ⌃⇧⇥ 前后移动，按住时也能用方向键，或者直接点击任意卡片。

按窗口隔离

切换器只列出你正在用的那个窗口的标签，每个窗口保留各自的历史。可在设置中关闭。

不会静默失灵

任一环节不可用时，⌃⇥ 会放行给 Chrome 自带的切换，而不是变成没反应的按键。

工作原理

TabFlick 由两部分组成，通过本地回环 WebSocket 通信。

┌─────────────────────────┐         ┌──────────────────────────┐
│  Chrome Extension (MV3) │  ws://  │  Swift Helper            │
│                         │◄───────►│                          │
│  · tabs.onActivated     │  :41573 │  · CGEventTap  (⌃⇥)      │
│  · captureVisibleTab    │         │  · NSPanel     (overlay) │
│  · tabs.update          │         │  · MRU state machine     │
└─────────────────────────┘         └──────────────────────────┘
扩展读不到键盘。 Tab 键在 Chrome 33 时就被移出了 chrome.commands 的可用键列表，任何扩展都无法绑定 ⌃⇥ —— 这是必须有一个原生进程的原因。
原生进程读不到标签。 标题、使用顺序、缩略图和执行切换都要通过 chrome.tabs API —— 这是必须有一个扩展的原因。

安装

需要 macOS 13+、Chrome 116+，以及 Xcode 命令行工具（xcode-select --install）。

  1. 克隆并编译

    git clone https://github.com/lifedever/TabFlick.git cd TabFlick/helper swift build -c release

  2. 加载扩展

    打开 chrome://extensions，右上角开启开发者模式，点「加载已解压的扩展程序」，选择仓库里的 extension 目录。

  3. 授予辅助功能权限

    首次运行会弹出授权提示。授权给启动它的那个终端应用，然后完全退出该应用再重新打开 —— 权限在进程启动时才读取。

    ./.build/release/tabflick

  4. 开始使用

    日志出现 ✅ Extension connected 即表示两端已接上。点击 Chrome 工具栏的 TabFlick 图标可以打开设置。

    日志文件在 ~/Library/Logs/TabFlick/tabflick.log ，排查问题从这里开始。

快捷键

Chrome 在前台时生效。

按键 效果
⌃ ⇥ 切换到上一个使用的标签
⌃ ⇥ ⇥ 按住 ⌃ 连点，沿使用历史继续往回走
⌃ ⇧ ⇥ 反向移动
⌃ ← → 按住 ⌃ 时用方向键移动游标
⌃ + 点击 直接切到点中的那个标签
